# Repository Map

This repository intentionally keeps generated research outputs and immutable 2026 prospective records under version control. Some files may look redundant at first glance but are retained because they support reproducibility, dashboard compatibility, or auditability.

## Top-level structure

### `.github/workflows/`
Automation and validation.

- `weekly-cfb-weather.yml` - scheduled live board, live site build, and prospective board snapshot.
- `prospective-close-capture.yml` - schedule-only near-kickoff market capture for CLV.
- `prospective-grade.yml` - safe postgame grading/rebuild.
- `prospective-ledger-tests.yml` - ledger/protocol self-test.
- `bankroll-helper-tests.yml` - bankroll presentation validation.
- `test-live-site.yml` - live website and model-output validation.
- `deploy-pages.yml` - GitHub Pages deployment.
- `manual-historical-research.yml` - full historical research rebuild when deliberately requested.
- `manual-climate-context-research.yml` - isolated latitude/local-weather-context run using the latest historical artifact; commits only its dedicated outputs and stadium-location reference.
- `climate-context-tests.yml` - synthetic end-to-end validation for the latitude and local-weather-context research path.

### `config/`
Small human-maintained configuration files.

- `settings.yml` - project/data/provider settings.
- `model_thresholds.yml` - model/live threshold configuration.
- `bankroll.yml` - bankroll helper defaults.
- `prospective_protocol_2026.yml` - versioned frozen 2026 prospective protocol.

### `src/`
Python source. Scripts are kept as CLI modules rather than notebooks.

Main functional groups:

- data/API: `cfbd_client.py`, historical pull scripts, `build_dataset.py`, team feature scripts;
- models/research: `model_bakeoff.py`, `edge_refinement.py`, `deep_research.py`, `validate_model_edges.py`, `climate_context_research.py`, backtest modules;
- live market/weather: `predict_week.py`, `nws_forecast.py`, `oddspapi_fallback.py`, `odds_api_fallback.py`, `run_live_week.py`;
- FCS: `fcs_model.py`, `fcs_research.py`, `fcs_research_labels.py`, `fcs_card_guard.py`;
- website/reporting: `build_live_dashboard.py`, `augment_dashboard_divisions.py`, `bankroll_helper.py`, `report.py`;
- prospective audit: `prospective_ledger.py`, `prospective_ledger_selftest.py`.

Some small compatibility wrappers remain in `src/` because removing them could break an older command even if the main workflow no longer calls that path. They are intentionally left alone unless a future cleanup proves they are safe to remove.

### `data/raw/` and `data/processed/`
Working data directories. Large generated datasets are not intended to be permanently committed. The `.gitkeep` files preserve the clean-clone directory structure.

Live GitHub Actions restores the processed training data from artifacts rather than expecting the full training dataset to live in Git.

### `outputs/`
Generated research and live products.

This directory is intentionally broad because the project has two distinct requirements:

1. preserve research diagnostics needed to explain how a rule was selected;
2. preserve the live/prospective audit trail needed to verify 2026 performance.

Do not casually delete or rename files here. Several files that contain identical content are deliberate aliases written by the producing script so old and new dashboard/research names remain compatible.

Examples include the `edge_refinement_*` and `edge_combo_grid_*` families. They may share the same blob/content because the code intentionally writes both naming conventions.

### `outputs/prospective/2026/`
The most sensitive directory in the project.

- immutable board snapshots and close captures are source-of-truth records;
- filenames embed a SHA-256 content-hash prefix;
- `manifest.csv` verifies immutable-file hashes;
- `official_entries.csv`, `graded_entries.csv`, `summary.csv`, and `prospective_summary.md` are derived products that can be rebuilt from the immutable history.

Do not manually edit or remove immutable snapshots/captures to tidy the repository.

### `docs/`
Generated GitHub Pages content. `docs/index.html`, `docs/research.html`, and `docs/fcs-research.html` are products of the build scripts, not the primary hand-maintained source.

Because this directory is the deployment source, human project notes belong in `documentation/` instead.

### `documentation/`
Human-maintained project documentation.

- `IN_SEASON_OPERATIONS.md` - end-to-end 2026 live/prospective workflow.
- `REPOSITORY_MAP.md` - this file.
- `FCS_REPRODUCIBILITY.md` - FCS environment/reproducibility note.
- `CLIMATE_CONTEXT_RESEARCH.md` - retrospective latitude/local-weather-context design, outputs, and prospective decision boundary.

## Cleanup policy

A file should be removed or moved only when all of the following are true:

1. it is not part of an immutable prospective record;
2. it is not generated by a current research/live workflow that expects the path;
3. it is not a deliberate compatibility alias;
4. it is not needed to reproduce a published historical conclusion;
5. code/workflow search shows no active reference or the replacement path is updated safely;
6. CI passes after the change.

This policy intentionally favors a slightly larger but auditable repository over an aggressively small repository that loses research provenance.
